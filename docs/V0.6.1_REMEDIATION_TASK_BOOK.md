# NewAPI Tools v0.6.1 修复任务书与验收标准

状态：运行时整改已完成；`v0.6.1` tag 的 Cosign v3 attestation 失败且未创建 GitHub Release。标签保持不可变，发行验收由 [`v0.6.2` 供应链恢复任务书](./V0.6.2_SUPPLY_CHAIN_RECOVERY_TASK_BOOK.md) 接续。
目标版本：`v0.6.1`
基线提交：`6594a818f4c0936b8757abe4581c7e482235e15c`（`v0.6.0`）
范围：用户管理、邀请充值分析、模型状态真值、Tool Store 安装/回滚、发票红票约束、配置耐久性、测试与发布治理。

## 1. 目标

本版本不是功能堆叠版本，而是生产可信度修复版本。完成后必须满足：

1. 用户筛选、分页、详情和邀请统计在相同条件下返回可重复、可解释的结果。
2. “邀请返利”不再把充值归因冒充真实奖励；汇总与明细使用同一查询口径。
3. stale、partial、unavailable、unreconciled 不再显示成绿色、空集或可信零。
4. 重装和升级失败均可恢复 Tool Store，不因镜像回滚继续复用不兼容 schema。
5. 主动探测不会因崩溃、跳过或落库失败突破预算。
6. 红票不能在缺少有效原票关系时冲减可信净额。
7. 所有修复均有自动化测试、故障注入证据和明确发布回滚路径。

## 2. 不可破坏边界

- 不修改 NewAPI schema，不在 NewAPI 数据库创建 sidecar 表、索引或触发器。
- 不进入模型代理请求链路；控制台异常不得影响 NewAPI 请求、扣费或登录。
- 自有持久化数据只写入 Tool Store。
- 缺失或不完整数据使用 `null` 与 `stale/partial/unavailable/unreconciled`，不得伪造 0。
- 财务金额继续使用最小货币单位整数或 API 十进制字符串，不新增 float 账务计算。
- 保留现有高风险操作的 RBAC、幂等、intent/outcome 和恢复记录。
- 不覆盖用户现有的未跟踪文件 `docs/MASTER_TASK_BOOK.md`。

## 3. 版本定义与兼容性

- 后端、前端和发行说明统一升级到 `0.6.1`。
- API 保持旧路由兼容，但允许增加字段、显式状态和专用详情路由。
- 不再默默接受无效筛选值；无效值改为 HTTP 400，schema 不支持的来源改为 422。
- Tool Store schema 仅在确有持久化需求时升级；每次迁移必须有 checksum、对象校验、备份和旧版本恢复测试。
- 若新增 schema，迁移版本必须单调递增，禁止修改既有迁移内容。
