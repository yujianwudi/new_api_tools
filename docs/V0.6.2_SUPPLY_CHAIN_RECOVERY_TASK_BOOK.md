# NewAPI Tools v0.6.2 供应链恢复任务书与验收标准

状态：执行中，只有 PR、exact-main、tag artifact、recovery drill 和 GitHub Release 全部通过后才能标记完成。

目标版本：`v0.6.2`

## 1. 背景与问题声明

`v0.6.1` tag workflow 使用 Cosign v3.1.2 时，在 `attest` 命令上传入已移除的 annotation 参数，普通签名完成但自定义 SLSA provenance 失败。由于不可变 tag 内的 recovery/consumer 又固定信任 tag OIDC 身份，默认分支修复无法安全自举回旧 tag。

本任务不移动或删除 `v0.6.1`，不把未完成证明的镜像包装成正式 Release；它以新 patch 版本修复正常发布与未来恢复的身份模型。

## 2. 目标

1. 正常 tag workflow 在 Cosign v3.1.2 下完成 sign、attest、verify 和 verify-attestation。
2. 安装/部署同时信任正常 tag build signer 与受保护 main recovery signer，并保持目标 tag/commit/manifest 绑定。
3. 消费端精确校验实际 amd64/arm64 子 digest，不只校验字符串格式。
4. recovery 只修复已存在且 digest 已知的 `v0.6.2+` manifest，不重建、不覆盖、不移动 alias。
5. 形成可重复的 PR、main、tag、artifact、recovery、Release 证据链。

## 3. 非目标

- 不恢复或创建 `v0.6.1` GitHub Release；
- 不移动、删除或重新创建任何已有 Git tag；
- 不把 recovery 扩展成可重建丢失镜像的发布器；
- 不降低 main/tag ruleset、OIDC certificate 或 manifest digest 门禁；
- 不把模型代理流量接入 NewAPI Tools；
- 不在本版本声称完成真实浏览器对比度与读屏人工验收。

## 4. 工作包

### WP1：Cosign v3 命令契约

- 普通 `sign`/`verify` 保留 `git_sha` 与 `tag` annotations。
- `attest`/`verify-attestation` 删除不支持的 annotation 参数。
- policy 文件使用 `.cue` 后缀，平台 map 使用闭合 CUE 结构。
- CI 安装固定 Cosign v3.1.2，并检查真实命令帮助面。

验收：任一 attestation 命令块包含 `-a`、policy 无 `.cue`、CLI 版本漂移或 command surface 改变时，PR 门禁失败。

### WP2：消费端平台绑定

- 从不可变 OCI index 提取唯一 `linux/amd64` 和 `linux/arm64` digest。
- 拒绝缺失、重复、额外真实平台和非法 digest。
- CUE policy 按 Cosign v3.1.2 实际生成的 in-toto `Statement/v0.1` 消费 SLSA v1 predicate，绑定精确值，并拒绝另一个合法 SHA-256 替换；离线门禁必须经过真实 attest-blob、bundle 验签和 DSSE 解码。
- 缺少 Docker Buildx 或支持 `-k` 的 `timeout` 时给出明确错误并在激活前失败；registry 查询在 120 秒后 TERM、再过 10 秒 KILL，部分输出也不得绕过失败关闭。

验收：install/deploy 正向 fixture 通过；subject、repository、ref、revision、tag、manifest、dependency 或任一平台 digest 伪造均失败。

### WP3：受保护 main recovery

- workflow_dispatch 必须来自 `refs/heads/main` 且 ref 受保护。
- `github.workflow_ref` 必须是固定 recovery 路径，`github.workflow_sha == github.sha`。
- 输入只接受 `v0.6.2+` strict semver annotated tag 和必填 exact `expected_manifest_digest`。
- 远端 base tag object 与 peeled commit 各恰好一条，fetch 到私有 ref 后再次验证，并要求 commit 可达 main。
- certificate identity/ref/SHA 绑定实际 main recovery；signature annotations 与 predicate revision/tag/tag object 绑定目标发行。

验收：非 main、未保护 ref、旧 tag、lightweight tag、tag object/peeled commit 漂移、非 main ancestor 或 workflow SHA 污染全部在 Sigstore 写入前失败。

### WP4：不可变 manifest 恢复

- exact image 必须已存在且 registry header/body digest 等于输入。
- recovery 禁止 build-push、禁止 `imagetools create`、禁止更新 minor alias。
- 校验双平台 revision、SBOM 与 BuildKit provenance 后再签名/证明。
- 每次 Sigstore 写入前后重验 Git tag 与 exact manifest。

验收：missing/mismatch 返回非零且无 package 写入；成功演练前后 exact digest、minor alias、tag object、peeled commit 完全不变。

### WP5：版本、文档与发行

- Go、frontend、Dockerfile、README、install/deploy 默认值统一为 0.6.2。
- `RELEASE_0.6.2.md` 与 README 固定同一个 installer commit/blob SHA-256，并保留 fail-closed manifest/revision 占位符。
- 通过 PR 合并到 main；禁止 squash/rebase，保留 merge commit。
- exact-main CI 绿后创建 annotated tag `v0.6.2`。
- tag workflow 全绿并完成实物验证后创建 non-draft、non-prerelease GitHub Release。

## 5. 安全不变量

| 不变量 | 拒绝条件 |
|---|---|
| Git tag 不可变 | object OID 或 peeled commit 与首次验证不同 |
| exact OCI manifest 不可变 | registry header/body/expected digest 任一不同 |
| 目标与执行身份分离 | recovery workflow SHA 被当成目标 revision，或目标 commit 被当成 main certificate SHA |
| provenance 完整 | subject、repository、ref、revision、tag、manifest、平台或 dependency 未精确绑定 |
| 财务/运行真值失败关闭 | 缺失数据被显示为 0、healthy 或 reconciled |
| 发布原子性 | 任一 required check 未完成就打 tag 或创建 Release |

## 6. 测试矩阵

- Shell：syntax、Cosign command block、真实 CLI surface、install/deploy identity、平台 digest mutation、事务回滚。
- Go：全量、race、vet、govulncheck、SQLite/MySQL/PostgreSQL、性能门禁。
- Frontend：67 项 Vitest/RTL/MSW、lint、TypeScript、build、npm audit。
- Workflow：YAML/actionlint、PR checks、exact-main checks、tag build、recovery dispatch。
- Artifact：OCI index cardinality、revision、SBOM、BuildKit provenance、Cosign signature annotations、自定义 SLSA policy、transparency log。

## 7. 发布与回滚

1. 合并前只允许在 feature branch/PR 运行测试，不创建 release tag。
2. main 全绿后记录 merge commit，并创建指向该 commit 的 annotated `v0.6.2`。
3. tag workflow 失败时保留 tag 与失败证据，不移动 tag、不创建 Release；修复必须使用下一个 patch 版本。
4. GitHub Release notes 在内存中替换 manifest/release commit 占位符，不修改已打 tag 的源码。
5. 部署失败恢复旧 `.env`、Compose identity、image digest 与匹配的 Tool Store Online Backup。
